# RQ2 classification summary — phase 1 + pilot (Nov 17–18, 2026)

## Method

Every mismatching project was classified at zip-entry level on within-E1
build-1/build-2 JAR pairs (`analysis/classify-entries.py`): entry
membership, entry order, per-entry SHA-256, and per-entry zip timestamps.
Raw codes: IDENTICAL, TIMESTAMP_ONLY, ORDERING, ORDERING+TIMESTAMP, CONTENT,
MIXED. Cases where the script reported CONTENT/MIXED because an *embedded*
JAR differed were resolved by recursive inspection of the embedded JAR.
diffoscope 259 reports (one representative differing artifact per project)
corroborate the sweep. A 20% re-classification sample (5 projects, 36 pairs)
was classified independently on within-E3 pairs: **36/36 raw-code
agreement** (`entries-reclass-e3.json`).

Codebook (maps to Sharma et al.'s 6-cause and Xiong et al.'s 14-pattern
taxonomies; two study-specific codes added):
- **TIMESTAMP** — zip entry timestamps set to build time.
- **ORDERING** — entry order (archive level) or generated-code constant order.
- **EMBEDDED_TIME** — build-time metadata embedded as file *content*
  (properties files, cache-buster strings). Maps to playbook step 6.
- **CI_CONTEXT** — ambient CI environment values leaking into artifacts.

Headline: **zero genuine content differences** (compiled code, resources)
anywhere in the baseline. Every mismatch is timestamps, ordering, embedded
build-time metadata, or CI context — never the code itself. Zero genuine
dependency drift in all 25 projects (only Maven resolver bookkeeping files
and arch-specific native payload paths differ in fingerprints).

## diffoscope corroboration

27 reports total: 8 pilot pairs (`pilot-diffs/`, text + HTML) and
19 phase-1 reports (`phase1-diffs/`, text). Agreement check: 17 of
19 phase-1 reports contain ONLY a zipinfo section (timestamps; no content
comparator fired); petclinic adds the 2 EMBEDDED_TIME properties files;
apollo adds apollo-git.properties + 6 nested JARs carrying it. Full agreement
with the entry-level sweep. Exception: graphql-jpa-query has no diffoscope
report (baseline JARs not retained); its classification rests on the
complete entry-level sweep (all 14 artifacts, every entry hashed).

## The boot-ui cases (targeted classification)

- **CI_CONTEXT (scm-url):** the 19 cross-only artifacts differ in exactly 2
  entries each (`META-INF/quarkus-extension.json`, `.yaml`), one field only:
  `scm-url` = the STUDY repo URL in E1, the target repo URL in E2/E3. Root
  cause: the harness passes `GITHUB_REPOSITORY` into the E1 container and
  the Quarkus plugin resolves scm-url from it. Harness artifact, disclosed,
  not a project defect; scope verified boot-ui-only.
- **ORDERING (generated bytecode):** after the fix normalized timestamps,
  18 `generated-bytecode.jar` files matched within every environment but
  differed E1-vs-ARM. All 18 pairs compared entry-by-entry: 0 timestamp
  diffs, 1–2 differing generated recorder classes each, with identical
  constant multisets in different constant-pool order (verified: 218 string
  runs, same multiset, 2 positions swapped). A genuine cross-environment
  ordering effect in Quarkus-generated bytecode, stable within each
  environment. No playbook step addresses it; recorded as a finding.
